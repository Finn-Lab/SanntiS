# SanntiS Memory Diagnostic — Initial Review

Date: 2026-03-05
Use case: FASTA + protein FAA + preprocessed InterProScan annotations (no IPS run)
Scenario: Metagenomic assembly with ~1M contigs

---

## Memory Issues by Severity

### Critical

**1. `transformIPS()` reads entire IPS file into memory — `BGCdetection.py:59`**

```python
with open(ipsFile, "r") as h:
    lines = h.readlines()          # entire file loaded as list
    fmt = "gff" if lines[0][:5] == "##gff" else "tsv"
    for l in lines:
```

For a 1M-contig metagenome, an IPS TSV with 5–10 annotations per protein and 5 proteins per contig is ~50–100M lines. `readlines()` materialises the whole thing as a Python list of strings before a single line is processed. The fix is trivial — read the first line for format detection, then iterate the open handle.

---

**2. All per-contig data structures live simultaneously in memory — `BGCdetection.py` throughout**

The `AnnotationFilesToEmerald` object accumulates and **never releases** six separate contig-keyed dictionaries:

| Attribute | Populated in | Contains |
|---|---|---|
| `self.entriesDct` | `transformIPS`, `transformEmeraldHmm` | `protein_id → [domain IDs]` |
| `self.contigsDct` | `transformCDSpredToCDScontigs` | `contig → [(protein_id, (start, end))]` |
| `self.annDct` | `buildMatrices` | `contig → np.float64 matrix of shape (n_cds, vocab_size)` |
| `self.annResults` | `predictAnn` | `contig → np.float64 array` |
| `self.looseClst`, `self.borderClst`, `self.typesClst` | `defineLooseClusters` | `contig → np.array` |

All six coexist from `buildMatrices()` through the end of `predictType()`. The worst offender is `annDct`: each contig gets a matrix of shape `(n_cds, vocab_size)` in **float64**. `vocab` is loaded from `post_filters.pickle` — if it has even 5,000 terms and you have 1M contigs averaging 5 CDSs each, that's `1M × 5 × 5000 × 8 bytes = 200 GB`. Even with a small vocab it's the dominant allocation.

Critically, `predictAnn()` already processes contigs one at a time (`for contig in self.annDct:`), so `annDct[contig]` could be deleted after each prediction — but it isn't, because `predictType()` later reads `annDct[contig]` again:

```python
# BGCdetection.py:305
tmat_ = np.sum(self.annDct[contig][gg], axis=0)
```

So you can't simply `del` after prediction without restructuring. The root issue is the design: everything is stored on `self` and nothing is freed between pipeline stages.

---

**3. `buildMatrices()` uses float64 matrices — `BGCdetection.py:147`**

```python
self.annDct[contig] = np.zeros((samps, len(self.vocab)))
```

Default dtype is `float64`. These matrices only ever hold 0 or 1 (binary domain presence), so `uint8` would give an 8× memory reduction for no loss. The model receives indices from `transformMat()`, not the raw matrices directly, but `predictType()` does `np.sum(self.annDct[contig][gg], axis=0)` — uint8 handles that fine.

### Significant

**4. `predictType()` materialises all BGC matrices in a list — `BGCdetection.py:289-312`**

```python
locations, matrix, typeLi = [], [], []
for contig in self.contigsDct:
    for k, g in groupby(...):
        ...
        matrix.append(tmat)  # one row per BGC found

pred = np.empty((len(matrix), len(claa)))
for nc, cla in enumerate(claa):
    pred[:, nc] = self.typeModel[cla].predict_proba(matrix)[:, 1]
```

All BGC feature vectors are collected before calling `predict_proba`. For metagenomic data with many BGCs this is fine (BGC count is bounded), but for very greedy settings (`--greed 2`) the list could be large. More importantly, each `tmat` has shape `(vocab_size,)` — same concern as `annDct`.

---

**5. `WriteOutput.gff3` accumulates all output lines before sorting — `WriteOutput.py:39, 187`**

```python
self.gff3 = []
# ... appended per CDS and per cluster across all contigs

self.gff3 = sorted(self.gff3, key=key)  # sorted in memory
for l in self.gff3:
    h.write(f"{l}\n")
```

With `--minimal False`, one string is appended per CDS (potentially 5M+ strings for 1M contigs). The in-memory sort then duplicates peak usage. With `--minimal True` (the default) this is bounded by number of detected BGCs, so it's fine for typical output but could spike if the `--refined` flag adds many `CLUSTER_border` entries.

## Focus for Next Steps

The two critical issues to address, in priority order:

1. **`annDct` dtype and lifetime**: change `np.zeros` dtype to `uint8`, and restructure
   `predictAnn()` + `predictType()` into a single per-contig pass so `annDct[contig]`
   can be freed after each contig is processed.

2. **Six coexisting dicts on `self`**: the design accumulates all intermediate state with
   no cleanup. A contig-streaming architecture where each contig is fully processed
   (build matrix → predict → classify → emit output) and then discarded would cap
   memory to O(1 contig) rather than O(all contigs).
